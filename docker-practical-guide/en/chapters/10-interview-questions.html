Chapter 10: Interview Questions

This chapter is a bank of real Docker interview questions, grouped by topic with short, precise answers. Read the question, try to answer it yourself, then reveal the solution.

The questions progress from the basics to advanced production topics.

⏱️ Reading time: — 📊 Level: All levels 🎤 60+ questions

✅ How to use this chapter

Don't memorize answers. Understand why, and connect them to what you did in the labs. A good interviewer asks "why" and "what if", not just definitions.

1. Docker and container fundamentals

🎤What is the "works on my machine" problem, and how does Docker solve it?
Show answer

It comes from differences in the runtime environment between machines (runtime version, settings, dependencies). Docker packages the app with its full environment into one Image that runs the same everywhere, eliminating that difference.

🎤What's the difference between a Virtual Machine and a Container?
Show answer

A VM emulates a whole machine with a guest OS on top of a Hypervisor, so it's heavy (gigabytes) and slow to boot. A Container is an isolated process that shares the host kernel, so it's light (megabytes), fast (seconds), and higher-density.

🎤What's the difference between an Image and a Container?
Show answer

An Image is a read-only template holding the app and its environment. A Container is a live, runnable instance of it. From one Image you run many Containers (like a Class and an Object).

🎤Does a container contain a full operating system?
Show answer

No. It contains only the app's files and environment, and shares the host OS kernel. That's why it's lighter and faster than a VM.

🎤Explain Docker's architecture.
Show answer

Three parts: the Docker Client (the commands you type), the Docker Daemon (the server that builds and runs), and the Registry (image store like Docker Hub). It works as a client/server model over a REST API.

🎤What is the role of the Docker Daemon?
Show answer

The background process (dockerd) that receives the Client's requests and actually executes them: building images, pulling them, and running and managing containers.

🎤List the stages of the container lifecycle.
Show answer

Created (docker create) → Running (start) → may pass through Paused → Stopped (stop) → Removed (rm). And docker run combines create and start.

🎤On Windows, where do containers actually run?
Show answer

The CLI (docker.exe) runs natively on Windows, but the Engine and containers run inside WSL 2 because containers need a Linux kernel. The Client sends commands via an API to the Daemon in WSL 2.

🎤Does Docker remove the need for a runtime?
Show answer

No. Docker doesn't replace the runtime — it bundles it. A Java app still needs a JRE, but now it lives inside the Image at a version we control.

2. Images, layers, and registries

🎤What is an Image made of?
Show answer

Of stacked read-only layers, each representing a change on top of the previous one, plus metadata describing how to run it.

🎤What's the benefit of splitting an Image into layers?
Show answer

Sharing and caching: shared layers are stored once, and building or pulling only processes the new layers — saving space and time.

🎤Where are a running container's changes written, and what happens on removal?
Show answer

In a thin writable layer on top of the read-only image layers (copy-on-write). That layer disappears when the container is removed, which is why we use a volume for persistent data.

🎤Explain the image name docker.io/library/nginx:1.27.
Show answer

docker.io = Registry, library/nginx = Repository (library/ is for official images), and 1.27 = Tag.

🎤What's the difference between a tag and a digest?
Show answer

A tag is a mutable name that can be repointed. A digest is a sha256 fingerprint of the content, immutable, so it guarantees pulling exactly the same content every time.

🎤Why should you avoid latest?
Show answer

It's a default tag that may point to a different version across machines or over time, so you lose reproducibility. Pin an explicit tag.

🎤Does docker tag copy the Image?
Show answer

No. It adds a new name (reference) pointing to the same layers. Removing one name doesn't remove the layers as long as another name points to them.

🎤What's required to push an Image to Docker Hub?
Show answer

docker login, an image name that starts with your username/organization (username/repo:tag), then docker push.

🎤How do you reduce an Image's size?
Show answer

A small base (jre not jdk), a multi-stage build, ordering instructions for caching, a .dockerignore, and combining RUN commands and removing temp files.

3. Running and managing containers

🎤What's the difference between docker run and docker start?
Show answer

run creates a new container from an Image and starts it. start restarts an existing stopped container without creating a new one.

🎤What do -d and -it mean?
Show answer

-d (detached): run in the background. -it = -i (keep input open) + -t (a TTY terminal), for an interactive session like a shell.

🎤What's the difference between docker stop and docker kill?
Show answer

stop sends SIGTERM and gives the process time for a clean shutdown, then SIGKILL. kill sends SIGKILL immediately with no grace period.

🎤What's the difference between exec and attach?
Show answer

exec runs a new process (like a shell) inside a running container. attach connects you to the main process (PID 1), and closing it may stop the container.

🎤Why does a container sometimes stop right after it starts?
Show answer

Because a container lives as long as its main process (PID 1) is alive. If the process ends (no long-running service), the container stops. Check the reason with docker logs.

🎤What are restart policies?
Show answer

no (default), on-failure on errors, always always, unless-stopped unless you stopped it manually — useful after a machine reboot.

🎤How do you remove all stopped containers?
Show answer

docker container prune. And to force-remove a running one: docker rm -f <name>.

4. Dockerfile

🎤What's the difference between COPY and ADD?
Show answer

Both copy files. ADD also auto-unpacks tar archives and downloads from a URL. We prefer COPY for clarity, and ADD only when explicitly needed.

🎤What's the difference between CMD and ENTRYPOINT?
Show answer

ENTRYPOINT is the fixed program that always runs. CMD is default arguments changeable at run time. They're often combined: entrypoint for the program, cmd for the arguments.

🎤What's the difference between RUN and CMD?
Show answer

RUN runs at build time and makes a layer (like installing a tool). CMD defines what runs at container run time.

🎤Why prefer exec form over shell form?
Show answer

Bracket (exec) form runs the program directly as PID 1, so SIGTERM reaches it and it stops cleanly. Shell form goes through a shell and breaks signal delivery, slowing the stop.

🎤What is the "build context" and the role of .dockerignore?
Show answer

The files in the path passed to docker build, sent to the Daemon. .dockerignore excludes what's not needed (like .git), shrinking the context and speeding the build.

🎤Why does instruction order affect caching?
Show answer

Changing an instruction invalidates its layer and everything after it. Putting rarely-changing things first (like dependencies) and changing code last reuses the most layers.

🎤Does EXPOSE publish the port?
Show answer

No, it's documentation only. Actual publishing to the host is done with -p host:container at run time.

🎤What is a multi-stage build and why use it?
Show answer

A build in several stages: one stage builds the artifact with build tools, and a runtime stage takes only the artifact. The result is a smaller, safer Image with no build tools or source code. COPY --from=build copies from an earlier stage.

🎤Why run a container as a non-root user?
Show answer

To limit the impact of any breach. We create a low-privilege user and run as it with USER, so an attacker doesn't gain broad privileges inside the container or on the host.

5. Storage (Volumes)

🎤Why is container data ephemeral?
Show answer

Because it's written to the container's own writable layer, which is deleted with it. To keep it, we store it in a volume independent of the container's lifecycle.

🎤What's the difference between a Named Volume and a Bind Mount?
Show answer

A Named Volume is managed by Docker in its own area, best for persistent, portable data. A Bind Mount maps a host path, best for development where changes reflect immediately.

🎤How do you persist PostgreSQL data?
Show answer

By mounting a Named Volume at its data directory: -v tasks-db:/var/lib/postgresql/data, so it survives container removal.

🎤Does docker rm remove the attached volume?
Show answer

No. The Named Volume stays (to protect the data). Remove it explicitly with docker volume rm, or docker volume prune for unused ones.

🎤What is an anonymous volume and why watch out for it?
Show answer

A volume with no name Docker creates automatically (often via a VOLUME instruction). It's hard to track and piles up, so we prefer naming volumes and cleaning unused ones with prune.

6. Networking

🎤What's the difference between the default bridge and a user-defined bridge?
Show answer

On a user-defined network, internal DNS works so containers recognize each other by name; on the default one they connect by IP only. So we create a user-defined network for any multi-container app.

🎤How do containers find each other?
Show answer

Via internal DNS on a shared user-defined network: a container's name becomes a hostname another container can connect to directly.

🎤What does -p 8080:80 do, and how is it different from EXPOSE?
Show answer

It publishes container port 80 on host port 8080 (syntax host:container), making it reachable from outside Docker. EXPOSE is documentation only and publishes nothing.

🎤Why not use localhost between two containers?
Show answer

Because localhost inside a container refers to the container itself, not another container or the host. Use the target container's name on the shared network.

🎤What is the host network and when is it used?
Show answer

It makes the container share the host's network stack directly, with no isolation and no need for -p. Useful for performance on Linux, but it loses isolation and works fully only on Linux.

🎤Can two containers on different networks communicate?
Show answer

No, unless one is connected to the other's network (docker network connect) or they share a network.

7. Docker Compose

🎤What is Docker Compose and when do you use it?
Show answer

A tool to describe and run a multi-container app from one compose.yaml file. Use it when your app is made of several services (app + database + cache…) managed together.

🎤What are the core sections of compose.yaml?
Show answer

services (containers), volumes (persistent storage), and networks (optional, since Compose creates one automatically).

🎤How do services find each other in Compose?
Show answer

Compose puts all services on one user-defined network, so each reaches another by the service name as a hostname via internal DNS.

🎤What's the difference between down and stop?
Show answer

stop only stops the containers. down stops and removes them along with the network. Named Volumes stay unless you use down -v.

🎤What does depends_on guarantee?
Show answer

Start order only, not readiness to accept connections. For readiness, use a health check with condition: service_healthy.

🎤How do you pass settings and secrets without writing them in the file?
Show answer

Via a .env file next to compose.yaml, then ${VAR} in the file. For production, dedicated secret tools are used, and values aren't committed to Git.

🎤What's the difference between image and build in a service?
Show answer

image uses a ready-made image from a registry. build builds the image from a local Dockerfile at run time.

8. Real apps and production

🎤How do you configure an app's database connection inside a container?
Show answer

Via environment variables (the 12-factor principle) instead of hard-coding settings, so they can change per environment without rebuilding the Image.

🎤What goes in place of the host in the database connection URL?
Show answer

The database service's name on the network (like db), because services recognize each other by name. Not localhost.

🎤How do you wait for the database to be ready before starting the app?
Show answer

depends_on alone guarantees start, not readiness. Add a health check on the database (pg_isready) and make the app wait with condition: service_healthy. It's also good for the app to retry on connection failure.

🎤How do you check an app's health inside a container?
Show answer

Via a health endpoint the app exposes (in Spring Boot: Actuator and /actuator/health), used in a HEALTHCHECK or by the orchestrator.

🎤Where do you put secrets in production?
Show answer

Always outside the Image: environment variables or a secret manager, passed at run time. Never baked into layers (they can be extracted) and never pushed to a public registry.

🎤Why care about JVM memory inside a container?
Show answer

The JVM must respect the container's memory limit, not the host's. Set -XX:MaxRAMPercentage to avoid exceeding memory and getting the container OOM-killed.

🎤How do you scan an Image for vulnerabilities?
Show answer

With tools like docker scout or Trivy, which scan the layers and packages against known-vulnerability databases, and are often integrated into the CI pipeline.

🎤What is the role of CI/CD with Docker?
Show answer

Automating building, scanning, and pushing the Image to a registry on every change, then deploying. Releases become consistent, reproducible, and fast, with no manual steps.

🎤How do you make an Image build reproducible?
Show answer

Pin base tags (and possibly a digest), build inside Docker with multi-stage (don't rely on your machine), use .dockerignore, and pin dependency versions.

Quick interview tips

  • Tie every answer to something you actually did (building an Image, a volume, a network, Compose).
  • When asked "why", mention the alternative and its downsides, not just the definition.
  • Be honest about what you don't know, then explain how you'd find out.
  • Review the common distinctions: Image/Container, CMD/ENTRYPOINT, volume/bind mount, default/user-defined bridge.
