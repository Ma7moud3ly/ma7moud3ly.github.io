Docker Desktop vs Docker Engine

There are two ways to run Docker, and the difference between them is a common source of confusion:

  • Docker Engine: Docker itself (the Daemon and the CLI). It runs natively on Linux.
  • Docker Desktop: a GUI app for Windows and macOS that runs Docker Engine inside a lightweight Linux machine in the background, and adds a UI, a dashboard, and tools.

The reason: containers rely on the Linux kernel. So on Windows and macOS, Docker needs a Linux layer running underneath — and that's where WSL comes in.

System Best fit How it works
Windows 10/11Docker DesktopVia WSL 2 (Linux kernel)
macOSDocker DesktopVia a lightweight VM
LinuxDocker EngineNatively on the system kernel

The role of WSL 2 on Windows

WSL 2 (Windows Subsystem for Linux) is a real Linux kernel running inside Windows. Docker Desktop uses it to run containers, so you get near-Linux performance without leaving Windows.

💡 Note

A modern Docker Desktop installer usually enables WSL 2 automatically. If you hit a problem, enable it manually with wsl --install in PowerShell as administrator, then restart.

❗ The CLI runs natively on Windows

A frequent point of confusion: WSL 2 is required for the Engine that runs containers, not for the command line. Remember that Docker splits into two parts (as we saw with docker version):

  • Docker CLI (Client) — the docker command you type, runs natively on Windows from PowerShell, CMD, or Windows Terminal.
  • Docker Engine (Server/Daemon) — the part that actually builds images and runs containers, runs inside WSL 2 because containers need a Linux kernel.

So when you run docker run in PowerShell, docker.exe handles the command locally on Windows, then sends it via an API to the Daemon inside WSL 2, which runs the container. You never leave PowerShell.

Installation steps

Windows / macOS

  1. Download Docker Desktop from the official site, docker.com.
  2. Run the installer and leave the "Use WSL 2 based engine" option enabled (on Windows).
  3. Restart if asked, then open Docker Desktop and wait until its status becomes "Running".

Common mistakes

⚠️ "Cannot connect to the Docker daemon"

This means the Daemon isn't running. On Windows/macOS: open Docker Desktop and wait for "Running". On Linux: sudo systemctl start docker.

⚠️ Always needing sudo on Linux

Add your user to the docker group (sudo usermod -aG docker $USER), then log out and back in.

⚠️ "port is already allocated"

The port (e.g. 8080) is already in use. Pick another one like -p 9090:80, or stop whatever is using the port.

Best practices

🔄 Keep Docker updated

Newer versions are more secure, faster, and support the latest features.

❓ Rely on --help

Faster than searching online, and it shows the options available in exactly your version.

🐧 On Linux: use the docker group

Avoid repeated sudo by adding your user to the group once.

Summary

Key ideas

  • Docker Engine runs on Linux; Docker Desktop runs it on Windows/macOS via a Linux layer.
  • On Windows, WSL 2 is the Linux kernel that actually runs the containers.
  • Verify the install with docker version (Client + Server) and docker info.
  • Every command follows one structure, has shortcuts, and --help is your friend.

Important commands

  • docker version / docker info
  • docker run hello-world / docker ps

Mistakes to avoid

  • Forgetting to start Docker Desktop / the docker service.
  • Using a busy port when mapping with -p.
