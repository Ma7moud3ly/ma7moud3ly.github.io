الفصل 4: الحاويات (Containers)

عرفنا أن الحاوية نسخة عاملة من Image. الآن نتعلّم كيف نُنشئها ونتحكّم بها: تشغيل، إيقاف، إعادة تشغيل، حذف، وقراءة السجلات، وفحص التفاصيل، والدخول إليها.

هذه الأوامر عملك اليومي مع Docker. ونفس المبادئ تنطبق على أي Image — من nginx إلى قاعدة بيانات إلى تطبيقك.

⏱️ زمن القراءة: — 📊 المستوى: مبتدئ 🧪 معمل تطبيقي واحد

أهداف التعلّم

بنهاية هذا الفصل ستعرف كيف:

  • تشغّل حاوية بأهم الأعلام: -d و -it و -p و -e و --name.
  • تدير دورة الحياة: start و stop و restart و rm.
  • تقرأ سجلات الحاوية وتتابعها لحظيًّا.
  • تفحص تفاصيل حاوية بـ inspect.
  • تدخل حاوية عاملة بـ exec لتشخيص المشكلات.

المتطلبات المسبقة

  • إنهاء الفصلين 2 و 3، مع Docker يعمل.
  • معرفة سحب الـ Images (docker pull).

تشريح أمر docker run

الأمر docker run ينشئ حاوية من Image ويشغّلها في خطوة واحدة. معظم قوّته في أعلامه (options):

العلم المعنى
-dتشغيل في الخلفية (detached) دون حجز الطرفية
-p 8080:80ربط منفذ المضيف بمنفذ الحاوية (host:container)
--name webإعطاء الحاوية اسمًا بدل المعرّف العشوائي
-e KEY=valueتمرير متغيّر بيئة إلى الحاوية
-itجلسة تفاعلية مع طرفية (interactive + TTY)
--rmحذف الحاوية تلقائيًّا عند توقّفها
--restartسياسة إعادة التشغيل عند الفشل أو الإقلاع

مقدّمة الخدمة مقابل الجلسة التفاعلية

هناك نمطان لتشغيل الحاويات:

  • خدمة في الخلفية (-d): مثل خادم ويب أو قاعدة بيانات — تعمل باستمرار وتعيد لك سطر الأوامر فورًا.
  • جلسة تفاعلية (-it): تدخل إلى shell داخل الحاوية لتجرّب الأوامر — تنتهي بخروجك منها.

❗ الحاوية تعيش ما دامت عمليتها الرئيسية حيّة

الحاوية ليست «جهازًا يعمل في الخلفية»، بل تلتفّ حول عملية واحدة (PID 1). إذا انتهت تلك العملية، توقّفت الحاوية. لذلك حاوية بلا عملية طويلة الأمد تتوقّف فور تشغيلها.

السجلات والفحص والدخول

أهم ثلاث أدوات لفهم ما يجري داخل حاوية دون إيقافها:

  • Logs: docker logs يعرض ما طبعته العملية على الخرج القياسي.
  • Inspect: docker inspect يعطي كل تفاصيل الحاوية (شبكة، منافذ، إعدادات) بصيغة JSON.
  • Exec: docker exec يشغّل أمرًا جديدًا داخل حاوية عاملة — غالبًا shell للتشخيص.

تشبيه من الواقع

✅ جهاز يعمل بلوحة تحكّم

أخطاء شائعة

⚠️ نسيان -d فتتجمّد الطرفية

تشغيل خدمة دون -d يحجز الطرفية بمخرجات الحاوية. أضف -d للخدمات، واترك التفاعلي لـ -it.

⚠️ «name is already in use»

اسم الحاوية يجب أن يكون فريدًا. احذف القديمة (docker rm) أو اختر اسمًا آخر.

⚠️ الحاوية تتوقّف فور تشغيلها

غالبًا لأن عمليتها الرئيسية انتهت (لا خدمة طويلة الأمد). راجع السبب بـ docker logs <name>.

⚠️ فقدان البيانات بعد rm

حذف الحاوية يمحو طبقة الكتابة الخاصة بها ومعها أي بيانات بداخلها. للبيانات الدائمة استخدم Volumes (الفصل 6).

أفضل الممارسات

🏷️ سمِّ حاوياتك

--name يجعل الأوامر أوضح من المعرّفات العشوائية.

🧹 --rm للتجارب

للحاويات المؤقّتة كي لا تتراكم حاويات متوقّفة على جهازك.

🔎 شخّص بـ logs و exec

قبل حذف حاوية فاشلة، اقرأ سجلّاتها وادخلها لفهم السبب.

💾 لا تخزّن بيانات داخل الحاوية

عاملها كسريعة الزوال؛ ضع البيانات في Volumes.

ورقة الأوامر (Cheat Sheet)

الأمرالوظيفة

docker run --rm -it img shجلسة تفاعلية مؤقّتة
docker ps / docker ps -aالحاويات العاملة / كلّها
docker logs -f <name>متابعة السجلات لحظيًّا
docker exec -it <name> shفتح shell داخل حاوية عاملة
docker inspect <name>تفاصيل الحاوية (JSON)
docker stop / start / restart <name>إدارة دورة الحياة
docker rm -f <name>حذف حاوية (بالقوة)
docker container pruneحذف كل الحاويات المتوقّفة

الخلاصة

أهم الأفكار

  • docker run ينشئ ويشغّل؛ قوّته في أعلامه (-d, -p, -e, --name).
  • الحاوية تعيش ما دامت عمليتها الرئيسية حيّة.
  • راقب دون إيقاف: logs وinspect وexec.
  • حذف الحاوية يمحو بياناتها — الحل في فصل Volumes.

أوامر مهمة

  • run / ps / logs / exec
  • stop / start / rm / prune

أخطاء تجنّبها

  • نسيان -d للخدمات.
  • افتراض بقاء البيانات بعد rm.
