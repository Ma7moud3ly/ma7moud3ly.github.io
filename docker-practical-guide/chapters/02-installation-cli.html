الفصل 2: التثبيت وواجهة الأوامر

في الفصل السابق فهمنا لماذا Docker. الآن نثبّته ونشغّل أول حاوية. من هنا ستنفّذ الأوامر بنفسك على جهازك.

سنرى الفرق بين Docker Desktop و Docker Engine، ودور WSL على Windows، وكيف نتأكّد أن التثبيت نجح، وبنية أوامر الـ CLI.

أهداف التعلّم

بنهاية هذا الفصل ستعرف كيف:

  • تفرّق بين Docker Desktop و Docker Engine ومتى تستخدم كلًّا منهما.
  • تشرح دور WSL 2 في تشغيل Docker على Windows.
  • تثبّت Docker وتتحقّق منه بـ docker version و docker info.
  • تشغّل أول حاوية بـ docker run hello-world.
  • تقرأ بنية أوامر الـ CLI وتستعين بـ --help.

المتطلبات المسبقة

  • إنهاء الفصل 1 (المفاهيم الأساسية للحاويات والـ Images).
  • جهاز بنظام Windows 10/11، أو macOS، أو Linux، مع صلاحيات تثبيت البرامج.
  • اتصال بالإنترنت لتنزيل Docker وأول Image.

Docker Desktop مقابل Docker Engine

هناك طريقتان لتشغيل Docker، والفرق بينهما مصدر حيرة شائع:

  • Docker Engine: هو Docker نفسه (الـ Daemon والـ CLI). يعمل أصلًا على Linux.
  • Docker Desktop: تطبيق رسومي لـ Windows و macOS يشغّل Docker Engine داخل جهاز Linux خفيف في الخلفية، ويضيف واجهة ولوحة تحكم وأدوات.

السبب: الحاويات تعتمد على نواة Linux. لذلك على Windows و macOS يحتاج Docker إلى طبقة Linux تعمل تحته — وهنا يأتي دور WSL.

macOSDocker Desktopعبر جهاز افتراضي خفيف
LinuxDocker Engineأصلًا على نواة النظام

دور WSL 2 على Windows

WSL 2 هو نواة Linux حقيقية تعمل داخل Windows. يستخدمها Docker Desktop لتشغيل الحاويات، فتحصل على أداء قريب من Linux دون مغادرة Windows.

💡 ملاحظة

يفعّل مثبّت Docker Desktop الحديث WSL 2 تلقائيًا في الغالب. إن واجهت مشكلة، فعّلها يدويًا بأمر wsl --install في PowerShell كمسؤول ثم أعد التشغيل.

❗ واجهة الأوامر تعمل أصلًا على Windows

نقطة يكثر الالتباس فيها: WSL 2 ضروري للـ محرّك (Engine) الذي يشغّل الحاويات، وليس لواجهة الأوامر. تذكّر أن Docker ينقسم إلى جزأين (كما رأينا في docker version):

  • Docker CLI (Client) — الأمر docker الذي تكتبه، يعمل أصلًا على Windows من PowerShell أو CMD أو Windows Terminal.
  • Docker Engine (Server/Daemon) — من يبني الـ Images ويشغّل الحاويات فعليًّا، ويعمل داخل WSL 2 لأن الحاويات تحتاج نواة Linux.

فعندما تنفّذ docker run في PowerShell، يعالج docker.exe الأمر محليًّا على Windows ثم يرسله عبر API إلى الـ Daemon داخل WSL 2 الذي يشغّل الحاوية. لا تغادر PowerShell إطلاقًا.

خطوات التثبيت

Windows / macOS

  1. نزّل Docker Desktop من الموقع الرسمي docker.com.
  2. شغّل المثبّت واترك خيار «Use WSL 2 based engine» مفعّلًا (على Windows).
  3. أعد تشغيل الجهاز إن طُلب منك، ثم افتح Docker Desktop وانتظر حتى تصبح حالته «Running».

المعمل التطبيقي

🧪 معمل 2: تجهيز بيئة العمل

هدف هذا المعمل أن تخرج بـ Docker يعمل على جهازك — وهو الأساس لكل الفصول القادمة.

  1. ثبّت Docker المناسب لنظامك (Desktop أو Engine).
  2. نفّذ docker version وتأكّد من ظهور قسمَي Client و Server.
  3. شغّل docker run hello-world وتأكّد من رسالة النجاح.
  4. شغّل docker run -d -p 8080:80 nginx، ثم افتح http://localhost:8080.
  5. نفّذ docker ps لرؤية الحاوية، ثم أوقفها بـ docker stop <container-id>.

المخرجات: بيئة Docker جاهزة ومُتحقَّق منها. في الفصل التالي نغوص في الـ Images وطبقاتها.

أخطاء شائعة

⚠️ «Cannot connect to the Docker daemon»

يعني أن الـ Daemon لا يعمل. على Windows/macOS: افتح Docker Desktop وانتظر حتى «Running». على Linux: sudo systemctl start docker.

⚠️ الحاجة إلى sudo دائمًا على Linux

أضف مستخدمك إلى مجموعة docker (sudo usermod -aG docker $USER) ثم سجّل الخروج والدخول مجددًا.

⚠️ «port is already allocated»

المنفذ (مثلًا 8080) مستخدَم بالفعل. اختر منفذًا آخر مثل -p 9090:80، أو أوقف ما يشغل المنفذ.

الخلاصة

أهم الأفكار

  • Docker Engine يعمل على Linux؛ وDocker Desktop يشغّله على Windows/macOS عبر طبقة Linux.
  • على Windows، WSL 2 هو نواة Linux التي تشغّل الحاويات فعليًّا.
  • تتحقّق من التثبيت بـ docker version (Client + Server) وdocker info.
  • كل الأوامر تتبع بنية واحدة، ولها اختصارات، و--help صديقك.

أوامر مهمة

  • docker version / docker info
  • docker run hello-world / docker ps

أخطاء تجنّبها

  • نسيان تشغيل Docker Desktop / خدمة docker.
  • استخدام منفذ مشغول عند ربط -p.
