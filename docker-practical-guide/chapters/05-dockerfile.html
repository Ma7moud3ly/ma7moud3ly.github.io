الفصل 5: Dockerfile

حتى الآن شغّلنا Images جاهزة. الآن نصنع Image خاصة بنا.

الـ Dockerfile ملف نصّي فيه خطوات بناء الـ Image. ينفّذ Docker هذه الخطوات واحدة تلو الأخرى، وكل خطوة تصنع طبقة. سنطبّق ذلك على تطبيق Java بسيط.

⏱️ زمن القراءة: — 📊 المستوى: متوسّط 🧪 معمل تطبيقي واحد

أهداف التعلّم

بنهاية هذا الفصل ستعرف كيف:

  • تفهم دور كل تعليمة في الـ Dockerfile.
  • تبني Image بأمر docker build.
  • تفرّق بين CMD و ENTRYPOINT، وبين COPY و ADD.
  • ترتّب التعليمات لتسريع البناء (layer caching).
  • تصغّر حجم البناء بملف .dockerignore.

المتطلبات المسبقة

  • إنهاء الفصل 3 (الـ Images والطبقات) والفصل 4 (تشغيل الحاويات).
  • محرّر نصوص لكتابة الكلاس والـ Dockerfile — لا حاجة إلى تثبيت Java على جهازك.
  • للمعمل: ملف jar لتطبيق يستمع على منفذ (مثلًا ناتج mvn package).

التعليمات الأساسية

هذه أكثر التعليمات استخدامًا. لكل واحدة عمل بسيط وواضح:

التعليمةماذا تفعل
FROMتختار Image الأساس (base image)
WORKDIRتحدّد مجلد العمل داخل الـ Image
COPYتنسخ ملفات من جهازك إلى الـ Image
ADDمثل COPY لكن مع مزايا زائدة (فكّ ضغط، تنزيل رابط)
RUNتنفّذ أمرًا وقت البناء
ENVتعرّف متغيّر بيئة
EXPOSEتوثّق المنفذ الذي يستمع عليه التطبيق
CMDالأمر الافتراضي عند التشغيل (يمكن تغييره)
ENTRYPOINTالأمر الثابت الذي يعمل دائمًا

COPY أم ADD؟

كلاهما ينسخ ملفات. الفرق أن ADD يفعل أشياء إضافية: يفكّ ملفات tar وينزّل من رابط. هذه الزيادة تسبّب مفاجآت.

✅ القاعدة

استخدم COPY دائمًا. لا تستعمل ADD إلا عند حاجة واضحة.

CMD أم ENTRYPOINT؟

الاثنان يحدّدان ما يعمل عند تشغيل الحاوية، لكن بينهما فرق بسيط:

  • ENTRYPOINT: البرنامج الثابت الذي يعمل دائمًا، مثل java -jar app.jar.
  • CMD: وسائط افتراضية يمكن للمستخدم تغييرها عند docker run.

اكتبهما دائمًا بصيغة الأقواس (exec form). هذه الصيغة تشغّل البرنامج مباشرةً:

❗ تجنّب صيغة النصّ (shell form)

كتابة ENTRYPOINT java -jar app.jar تشغّل البرنامج عبر shell. عندها لا يكون برنامجك هو PID 1، ولا تصله إشارة الإيقاف بشكل صحيح، فيبطؤ إيقاف الحاوية. الزم صيغة الأقواس.

سياق البناء وملف .dockerignore

عند docker build يرسل Docker محتوى المجلد كله إليه (build context). ملف .dockerignore يستبعد ما لا نحتاجه (مثل .git)، فيصبح البناء أسرع والـ Image أنظف.

ترتيب التعليمات و caching

💡 ماذا عن EXPOSE و -p؟

هذا التطبيق يطبع جملة ثم يخرج؛ لا يستمع على أي منفذ، فلا يوجد ما ننشره. لذلك EXPOSE و-p بلا معنى هنا. نستخدمهما فقط مع تطبيق يستمع على منفذ (مثل خادم ويب): نضيف EXPOSE 8080 في الـ Dockerfile ونشغّل بـ -p 8080:8080 — وهو ما نفعله في المعمل.

💡 جرّب الـ caching

أعد docker build دون تغيير شيء — سينتهي فورًا لأن الطبقات جاهزة في الـ cache. غيّر رسالة Main.java وأعد البناء، وسيُعاد تنفيذ javac وحده.

  1. جهّز ملف jar لتطبيق يستمع على المنفذ 8080 (مثلًا mvn package).
  2. أنشئ Dockerfile يعتمد على runtime فقط ويكشف المنفذ:
  3. أضف ملف .dockerignore (يستبعد .git وغيره).
  4. ابنِ الـ Image: docker build -t my-app:1.0 .
  5. انشر المنفذ وشغّلها: docker run -d --name app -p 8080:8080 my-app:1.0، ثم افتح http://localhost:8080.

أخطاء شائعة

⚠️ ترتيب يكسر الـ cache

نسخ الكود قبل الـ dependencies يعيد تحميلها مع كل تعديل صغير. ضع ما نادرًا يتغيّر أولًا.

⚠️ استخدام ADD بلا داعٍ

سلوكه الزائد قد يفاجئك. الافتراضي دائمًا COPY.

⚠️ ظنّ أن EXPOSE ينشر المنفذ

EXPOSE توثيق فقط. النشر للمضيف يتم بـ -p عند التشغيل.

⚠️ Image أساس ثقيلة

استخدام jdk بدل jre وقت التشغيل يكبّر الـ Image بلا فائدة. اكتفِ بـ runtime المناسب.

أفضل الممارسات

🧱 رتّب للـ caching

النادر التغيّر أولًا، والكود المتغيّر أخيرًا، فيصبح البناء أسرع.

🚫 .dockerignore دائمًا

يستبعد .git وملفات غير لازمة، فيصغُر البناء والـ Image.

📎 صيغة الأقواس

استخدم ["...", "..."] لسلامة الإشارات وإيقاف نظيف.

📌 ثبّت وسم الأساس

eclipse-temurin:21-jre لا :latest.

الخلاصة

أهم الأفكار

  • الـ Dockerfile ملف خطوات؛ كل تعليمة تصنع طبقة.
  • استخدم COPY، وENTRYPOINT بصيغة الأقواس.
  • رتّب التعليمات لتستفيد من الـ caching، واستبعد الزائد بـ .dockerignore.
  • EXPOSE توثيق فقط؛ النشر بـ -p.

عناصر مهمة

  • FROM / WORKDIR / COPY / ENTRYPOINT
  • docker build -t name:tag .

أخطاء تجنّبها

  • ترتيب يكسر الـ cache.
  • صيغة النصّ في ENTRYPOINT، و Image أساس ثقيلة.
