الفصل 3: الـ Images

الـ Image هي المكوّن الذي نبنيه وننقله وننشره. في هذا الفصل نفتحها من الداخل: مِمَّ تتكوّن، ولماذا هي مبنيّة من طبقات، ومن أين نجلبها وإليها ندفعها.

فهم الطبقات سيغيّر طريقة كتابتك للـ Dockerfile لاحقًا، ويجعل الـ Images أصغر وأسرع.

⏱️ زمن القراءة: — 📊 المستوى: مبتدئ 🧪 معمل تطبيقي واحد

أهداف التعلّم

بنهاية هذا الفصل ستعرف كيف:

  • تصف الـ Image كطبقات (layers) ثابتة مكدّسة.
  • تشرح كيف تُشارَك الطبقات بين الـ Images لتوفير المساحة والوقت.
  • تقرأ اسم الـ Image الكامل: registry/repository:tag.
  • تفرّق بين الـ Registry والـ Repository والـ Tag.
  • تسحب الـ Images وتعيد وسمها وتدفعها إلى Docker Hub.

المتطلبات المسبقة

  • إنهاء الفصل 2، مع Docker يعمل (docker run hello-world ينجح).
  • حساب مجاني على hub.docker.com (سنحتاجه في قسم الدفع push).

ما الـ Image فعليًّا؟

الـ Image قالب ثابت للقراءة فقط. يحتوي كل ما يحتاجه التطبيق ليعمل: نظام ملفات، مكتبات، بيئة تشغيل، وإعدادات. لكنها ليست ملفًّا واحدًا، بل طبقات (layers) مكدّسة.

الطبقات (Layers)

كل خطوة في بناء الـ Image تضيف طبقة جديدة فوق سابقتها. كل طبقة ثابتة (read-only) وتمثّل التغيير الذي أحدثته تلك الخطوة فقط.

مثال على تكديس الطبقات لـ Image تطبيق نموذجي:

  • طبقة أساس: توزيعة Linux صغيرة (base image).
  • طبقة فوقها: بيئة التشغيل (runtime) والمكتبات.
  • طبقة عليا: ملفات تطبيقك.

عند تشغيل حاوية من الـ Image، يضيف Docker طبقة كتابة رقيقة (writable layer) فوق طبقات الـ Image الثابتة. كل تغيير يحدث أثناء عمل الحاوية يُكتب هنا فقط، دون المساس بالـ Image.

✅ لماذا الطبقات مهمّة؟

الطبقات تُخزَّن مرة واحدة وتُشارَك بين كل الـ Images والحاويات. إذا اشتركت عشر Images في نفس طبقة الأساس، فهي على القرص مرة واحدة. ولهذا يكون pull والبناء أسرع: تُنزَّل الطبقات الجديدة فقط.

اسم الـ Image: Registry و Repository و Tag

اسم الـ Image الكامل يتكوّن من ثلاثة أجزاء:

  • Registry: مكان تخزين الـ Images (الافتراضي docker.io أي Docker Hub).
  • Repository: اسم الـ Image نفسها (الـ Images الرسمية تحت library/).
  • Tag: إصدار محدّد (الافتراضي latest).

❗ احذر الوسم latest

latest ليس «الأحدث دائمًا»، بل مجرّد وسم افتراضي قد يشير إلى أي إصدار. اعتمد على وسم صريح مثل nginx:1.27 لتضمن نتائج قابلة للتكرار (reproducible).

الـ Digest: مرجع ثابت لا يتغيّر

الوسم قد يُعاد توجيهه إلى محتوى مختلف لاحقًا. أما الـ digest (بصمة sha256) فيشير إلى محتوى محدّد لا يتغيّر أبدًا — مفيد عندما تريد تثبيتًا صارمًا:

السجلات (Registries) و Docker Hub

الـ Registry مخزن للـ Images. أشهرها Docker Hub (العام والافتراضي)، وهناك سجلات أخرى مثل GitHub Container Registry (ghcr.io) وسجلات خاصة داخل الشركات.

على Docker Hub تجد أنواعًا من الـ Images:

موثّقة (Verified Publisher)eclipse-temurinمن جهات معروفة
مجتمعيةusername/appمن أي مستخدم — تحقّق منها

تشبيه من الواقع

✅ شرائح شفّافة مكدّسة

تخيّل الطبقات كشرائح بلاستيكية شفّافة مرسوم على كلٍّ منها جزء من الـ Image. عندما تكدّسها تحصل على الـ Image الكاملة. لتغيير طبقة عليا لا تحتاج إعادة رسم الطبقات السفلى — تعيد فقط الشريحة التي تغيّرت.

وإن عرفت Git، فالطبقات تشبه الـ commits: كل واحدة تسجّل التغيير فوق ما قبله، والـ Registry يشبه GitHub لكن للـ Images.

المعمل التطبيقي

🧪 معمل 3: استكشاف base image

في الفصول القادمة سنبني Image لتطبيقنا فوق base image تحمل بيئة تشغيل Java. لنتعرّف عليها الآن.

  1. اسحب base image Java: docker pull eclipse-temurin:21-jre.
  2. قارن حجمها بحجم alpine عبر docker images. لماذا الفرق؟
  3. استعرض طبقاتها بـ docker history eclipse-temurin:21-jre.
  4. أعد وسمها باسمك: docker tag eclipse-temurin:21-jre YOUR_USER/java-base:21.
  5. (اختياري) ادفعها إلى Docker Hub.
  6. احذف الوسم الذي أنشأته بـ docker rmi YOUR_USER/java-base:21 ولاحظ أن الـ Image الأصلية تبقى.

المخرجات: base image Java جاهزة محليًّا — هي التي سنبني فوقها في فصل Dockerfile.

أخطاء شائعة

⚠️ الاعتماد على latest

قد يتغيّر ما يشير إليه latest بين جهازين أو مع الوقت، فتحصل على نتائج غير متوقّعة. ثبّت وسمًا صريحًا.

⚠️ نسيان docker login قبل الدفع

محاولة push دون تسجيل دخول أو دون تسمية الـ Image باسم مستخدمك تفشل بخطأ صلاحيات (denied).

⚠️ الخلط بين Repository و Tag

nginx مستودع (repository)، و1.27 وسم (tag) داخله. المستودع الواحد يحوي عدة وسوم/إصدارات.

أفضل الممارسات

📌 ثبّت وسومًا صريحة

استخدم postgres:16 لا postgres:latest لضمان التكرار.

🛡️ فضّل الـ Images الرسمية والموثّقة

أقل مخاطرة أمنية وأفضل صيانة من الـ Images المجتمعية المجهولة.

🪶 ابدأ من أساس صغير

base image أصغر = طبقات أقل، سحب أسرع، ومساحة هجوم أضيق.

الخلاصة

أهم الأفكار

  • الـ Image مبنيّة من طبقات ثابتة مكدّسة، والحاوية تضيف فوقها طبقة كتابة.
  • الطبقات تُخزَّن مرة وتُشارَك، فتوفّر المساحة وتسرّع السحب والبناء.
  • اسم الـ Image = registry/repository:tag، والافتراضي Docker Hub وlatest.
  • الـ digest مرجع ثابت، بينما الوسم قابل للتغيير.

أوامر مهمة

  • docker pull / docker images / docker history
  • docker tag / docker login / docker push

أخطاء تجنّبها

  • الاعتماد على latest.
  • نسيان تسجيل الدخول أو تسمية الـ Image باسمك قبل الدفع.
