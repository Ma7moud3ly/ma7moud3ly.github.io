Chapter 4: Containers

We know a container is a running instance of an Image. Now we learn how to create and control it for real: run, stop, restart, remove, plus reading logs, inspecting details, and getting inside it.

These commands are your daily work with Docker, and the same principles apply to any Image — from nginx to a database to your own app.

Learning objectives

By the end of this chapter you'll know how to:

  • Run a container with the key flags: -d, -it, -p, -e, and --name.
  • Manage the lifecycle: start, stop, restart, and rm.
  • Read a container's logs and follow them live.
  • Inspect a container's details with inspect.
  • Get into a running container with exec to diagnose issues.

Anatomy of docker run

docker run creates a container from an image and starts it in one step. Most of its power is in its flags (options):

Flag Meaning
-dRun in the background (detached) without holding the terminal
-p 8080:80Map a host port to a container port (host:container)
--name webGive the container a name instead of a random ID
-e KEY=valuePass an environment variable to the container
-itAn interactive session with a terminal (interactive + TTY)
--rmAutomatically remove the container when it stops
--restartRestart policy on failure or boot

A background service vs an interactive session

There are two ways to run containers:

  • A background service (-d): like a web server or a database — it runs continuously and returns your prompt immediately.
  • An interactive session (-it): you drop into a shell inside the container to try commands — it ends when you exit.

❗ A container lives as long as its main process

A container isn't "a machine running in the background" — it wraps a single process (PID 1). If that process ends, the container stops. So a container with no long-running process stops the moment it starts.

Logs, inspect, and exec

The three most important tools for understanding what's happening inside a container without stopping it:

  • Logs: docker logs shows what the process printed to standard output.
  • Inspect: docker inspect gives every detail of the container (network, ports, settings) as JSON.
  • Exec: docker exec runs a new command inside a running container — usually a shell for diagnosis.

Real-world analogy

✅ A machine with a control panel

Picture the container as a running machine: a power button (start/stop), a log screen showing what it's doing (logs), a spec sheet describing its state (inspect), and a maintenance door you step through to check the inside (exec) — all without taking the machine apart.

Common mistakes

⚠️ Forgetting -d, so the terminal freezes

Running a service without -d ties up the terminal with the container's output. Add -d for services, and keep -it for interactive use.

⚠️ "name is already in use"

A container name must be unique. Remove the old one (docker rm) or pick a different name.

⚠️ The container stops immediately

Usually because its main process ended (no long-running service). Check the reason with docker logs <name>.

⚠️ Losing data after rm

Removing a container erases its writable layer and any data inside it. For persistent data, use Volumes (Chapter 6).

Best practices

🏷️ Name your containers

--name makes commands clearer than random IDs.

🧹 --rm for experiments

For throwaway containers, so stopped containers don't pile up on your machine.

🔎 Diagnose with logs and exec

Before deleting a failing container, read its logs and step inside to understand why.

💾 Don't store data inside the container

Treat it as ephemeral; put data in Volumes.

Cheat sheet

CommandWhat it does
docker run -d --name x -p 8080:80 imgRun a service in the background
docker run --rm -it img shA temporary interactive session
docker ps / docker ps -aRunning containers / all of them
docker logs -f <name>Follow logs live
docker exec -it <name> shOpen a shell in a running container
docker inspect <name>Container details (JSON)
docker stop / start / restart <name>Manage the lifecycle
docker rm -f <name>Remove a container (forcefully)
docker container pruneRemove all stopped containers

Summary

Key ideas

  • docker run creates and starts; its power is in the flags (-d, -p, -e, --name).
  • A container lives as long as its main process is alive.
  • Observe without stopping: logs, inspect, and exec.
  • Removing a container erases its data — the fix is in the Volumes chapter.

Important commands

  • run / ps / logs / exec
  • stop / start / rm / prune

Mistakes to avoid

  • Forgetting -d for services.
  • Assuming data survives rm.
